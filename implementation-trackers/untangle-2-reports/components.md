- `TrackSidebar.tsx`, `TrackSidebarRow.tsx`, `MasterSidebarRow.tsx`, `TrackLane.tsx`, `ClipComponent.tsx`, `timeline-workspace.tsx`, `automation-lane.tsx` form the arrangement view.

## 3. Candidate root fixes

- **R1 One effect-kind registry in the UI layer.** Define, once, per audio-effect kind: label, view component, params normalizer, state accessor (`state.enabled` vs `enabled`), default params, equality, export-row builder. EffectsPanel, the context-menu controls, the card Switch, `paramsEqualByKind`, `defaultPresetStepByKind`, `runtimeInstanceForParams`, `exportRowForRuntime`, `instanceBindingByKind` and the public `audioEffects` object are all derived from it (a generic `audioEffects.byKind[kind]` plus typed helpers). Normalize all effects to the `{version, state}` envelope shape at the boundary so the `enabled` special case disappears. Resolves H1, H2, H3, H4, H5, S7, X3 (reverb defaults), part of H6; shares the registry with the cross-cutting effect-kind owner. Risk: medium-high; behavior must stay the same for persisted params (compressor/saturator/delay/reverb/eq use the flat shape).
- **R2 A declarative device-view helper for plain effects.** One `<ParameterKnob id=... />` (or a device-descriptor-driven view) that builds the automation quartet from `parameterId` and the shared automation descriptor, so Chorus/Flanger/Phaser/Tremolo/AutoPan/Ensemble/LoFi/AutoFilter/Utility become thin descriptors. Resolves H6, S6, part of S7. Risk: medium (visual parity; AGENTS.md prefers explicit UI, so only extract the repeated knob wrapper, not a config model).
- **R3 Instrument kind contract table used by the panel state.** Route synth through `INSTRUMENT_CONTRACTS`, make `setForTarget/updateForTarget` helpers take a kind, and keep one "instrument of kind or default" function. Resolves H7, N5, X3 (synth cases). Risk: medium.
- **R4 Make every user action a command (name, handler, can-run, shortcut, undo label)** so toolbar, menus, desktop application menu, keyboard handler, shortcut dashboard and error reporting read one list. Resolves H8, H10, X1 (Timeline.tsx part: the command wrapper reports one outcome), X4. Risk: high (large wiring change in Timeline.tsx).
- **R5 Plugin-catalog service owner** (trust acknowledgement, scan, auto-heal, change notification as a subscribable store, not a window event). Resolves H9, N3 (part), pieces of the `localStorage` guard. Risk: low-medium.
- **R6 Move models out of components** (persisted effect state, parameter gesture owner, local effects view, processor edit registry, browser tree/drag, automation seed/persist state, device value formatting types) into `src/lib` (or a package) so hooks/lib never import `~/components`. Resolves N1, N7, H13 (partly), and half of N2 (the desktop acceptance observer). Risk: low (moves + import rewrites), but touches the certification anchor files listed in the pr62 plan (`parameter-gesture-owner.ts`, `Timeline.tsx`), so run the plan's CERT recipe.
- **R7 Outcome-typed async actions** (`{ok}|{failed, reported}`) for effects add/remove/reorder, drops and keyboard delete, so call sites stop writing `.catch(() => undefined)`. Resolves X1 (EffectsPanel, effects state, drag), part of H4. Risk: medium.
- **R8 Delete dead UI**: nav-user.tsx, ui/sidebar.tsx, badge.tsx, avatar.tsx, separator.tsx, sheet.tsx, skeleton.tsx (if still unused after rg), and remove their knip `ignoreFiles` entries. Resolves S1. Risk: none for behavior (verify no dynamic reference).
- **R9 Test fixtures out of src/components** (a `src/test-fixtures/browser/` or `tests/` folder). Resolves H14. Risk: low.
