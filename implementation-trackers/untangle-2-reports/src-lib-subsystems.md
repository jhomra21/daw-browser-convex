## 3. Candidate root fixes

1. **One table per history entry type (name, validator, builder, executor, persister, merge rule).** Make `undo/` declare each entry kind once as a record `{ validate, apply(direction), persist(direction), merge? }` and derive `HistoryEntry`, `isHistoryEntryData`, `execHistoryEntry` and `mergeEntry` from the table, so adding an entry touches one file. 2. **Effect kind registry consumed by undo/local-control/repository.** Replace the hand lists with lookups from `AUDIO_EFFECT_CONTRACTS` (it already has `normalizeParams` per kind): `persistHistoryEffectParams` becomes a map from kind to the operation kind and normalizer, `localEffectKind` uses `isAudioEffectKind`, `exec.ts:434-445` uses the same registry (and stops silently skipping kinds), sidechain-capable kinds become a `sidechainTarget` flag on the contract. Resolves: duplicated storage types, classifier, ~30 swallowed cleanup sites, encode-recording-wav's re-opened directory. Risk: medium (cleanup ordering must stay identical; OPFS tests exist: native-offline-pcm-spool.test.ts, recording-temp-storage.test.ts).
4. **One recording worker session.** Move `WorkerEndpoint`, `Deferred`, `createBrowserRecordingWriter` and the deadline timer pattern into one `recording-worker-session` that owns "request with deadline, abort, terminate"; remove benchmark-sab-worker.ts and `recordNativeBlockTiming` if confirmed unused. 5. **Export job as phases with one cleanup scope.** Split `run-export-job.ts` into (a) prepare (snapshot, preload, stretch), (b) render backend (`native` or `portable` object chosen once, replacing `nativeRendererRequired` branches), (c) encode/save, with one `using`-style cleanup scope shared by mixdown and stems that logs cleanup failures the same way. Resolves: the three preferences hidden-link items. Risk: low-medium (existing 381-line test file covers versions).
8. **Local project row kinds and stored-value guards in one module** (`~/lib/local-project-rows`): kind constants, `LocalProjectStoredObject`, guards; used by repository, local-control model/projector, export capture. Plus one `recoverableActionKinds` set used by service, execution and recovery. Resolves: the two local-control/repository duplicate items. Risk: low.
