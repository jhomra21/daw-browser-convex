# Untangle step 2: packages/audio-engine, audio-core-contract, audio-core-wasm, waveforms

Read-only research. HEAD of branch anti-slop-update. Evidence: rg across the whole repo, a token-index script for dead exports (/tmp/untangle2/scratch/audio-engine/dead.txt), and `git log --name-only -n 400 -- <area>` (280 commits touched the area).

## 1. Area summary

- **audio-engine** (about 35K non-test lines in 120 source files, 52 subpath exports in package.json). It is not one module but five products in one package:
  1. The live Web Audio engine: `audio-engine.ts` (class AudioEngine, 1380 lines, about 90 public methods) composing `live-mixer-runtime.ts`, `master-fx-runtime.ts`, `effect-chain-transaction.ts`, `chain-admission.ts`, `instrument-runtime.ts` (synth, sampler, drum-rack, granular runtimes), `clip-scheduler.ts`, `metering-runtime.ts`, `metronome-runtime.ts`, `recording/*`, `effects/*`, `mixer/*`.
  2. Offline export: `export-mixdown.ts` (1631), `mixer/apply-offline-routing.ts`, `export-fidelity/*`, `streaming-*`, `export-encoding.ts`, `portable-export-*`.
  3. The portable-core projection: `mixer/graph-contract.ts` (AudioCoreGraphSnapshot builder), `portable-session-compiler.ts`, `portable-clip-projector.ts`, `portable-frame-scheduling.ts`, `portable-wasm-protocol.ts`, `backends/wasm-audio-worklet-backend.ts`.
  4. The Electron native wire: `native-host-wire.ts` (1116), `live-native-projection.ts`, `native-pcm-chunking.ts`, `native-stretch-preparation.ts`.
  5. Time-stretch and media: `audio-stretching.ts` (2136), `audio-stretch-cache.ts`, `prepared-stretch-store.ts` (1621), `portable-stretch-*`, `media-pages.ts`.
  Also: characterization pages (`*-characterization.ts`), `test-support/`.
- **audio-core-contract**: `src/index.ts` (1301 lines) holds the portable ABI types and per-processor state encoders. `src/generated/processor-contract-metadata.ts` and `native/audio-core/generated/processor_contract_generated.h` are produced by `scripts/generate-contract.ts` from two JSON schemas. It has no dependencies.
- **audio-core-wasm**: one 248-line loader/validator for the wasm artifact manifest. It depends on audio-core-contract.
- **waveforms**: peak extraction, IndexedDB peak store (`peak-db.ts`), in-memory asset store (`asset-store.ts`), arrangement PCM tile scheduler, level of detail, canvas drawing. It depends only on @daw-browser/shared.
- Dependencies in: `src/` (UI, hooks, lib), `apps/desktop`, `tools/acceptance`, `native/audio-core/tests`. The public JS worklets and workers (`public/audio-worklets`, `public/audio-workers`, 6400 lines) are hand-written copies of constants and protocol that live here in TS.
- Dependencies out: shared, timeline-core, desktop-protocol (3 files), plugin-host-protocol (type import in `native-host-wire.ts:18`), mediabunny, @noble/hashes. audio-engine imports audio-core-contract and audio-core-wasm by relative path (7 files), not by package name.
- Co-change evidence (400-commit window, pairs of files in the same commit): live-mixer-runtime and master-fx-runtime 39; audio-engine and live-mixer-runtime 27; audio-engine and export-mixdown 25; live-mixer-runtime, master-fx-runtime and apply-offline-routing 20-23 each; effects/chain.ts with each of live, master, offline and export 14-18; native-host-wire.test with portable-session-compiler 10; audio-core-contract/src/index.ts with portable-session-compiler 10. The most-changed files are export-mixdown 52, live-mixer-runtime 50, audio-engine 50, master-fx-runtime 42, portable-wasm-host.test 35.

## 3. Candidate root fixes

1. **One effect-kind descriptor table in a lower package.** Define each kind once as a record (kind id from the generated registry, runtime class: eq/compressor/saturator/delay/reverb/static-worklet, worklet asset, input count, declared latency and tail function, layout rule, detector capability, nonlinear flag, portable support) and derive `isStaticWorkletKind`, `isModulationKind`, `manifest()`, `kindId`, the capability lists (including the public JS capability file, generated at build), timing, layout, `nonlinearMaster` and the stage-config mapping from it. Resolves: all five `isStaticWorkletKind` copies, the kind ladders in chain.ts, timing.ts, transaction, offline routing, graph-contract, channel-layout, native-host-wire, live-native-projection, the `kindId` literals, the capability matrix copies, export-mixdown.ts:1258, and the 12 unused instance interfaces. Risk: medium-high; the behavior must stay identical for each kind, and the table sits in the cross-cutting worker's scope (coordinate). Characterize first with the existing graph-contract and capability tests.
2. **Make the generated contract the only source of layout facts.** Let the contract package export decoders (`processorEnabled(state)`, `processorOutputLayout`, `processorLatency`) next to the encoders so native-host-wire.ts stops reading raw offsets, and drive channel-layout.ts from the same function. Resolves: the native-host-wire byte-offset item, the flanger/phaser divergence, part of the timing literals. Risk: medium (layout rules must be compared to native first).
3. **One effect-chain runtime parameterized by owner.** The track and master runtimes become two instances of one chain-owner (state maps, meters, bypass, rebuild/settle, admission replay) with a small routing adapter each, so `closeInstanceState`, meter binding, `bypassStaticWorklet`, the stage-config mapping and the in-place test exist once. Resolves: the master/live twins and the 20-field host. Risk: high (realtime ordering, fault handling, the superseded/joined semantics; both runtimes have large test suites that must stay green).
4. **Shared protocol constants module for TS and JS.** Put page frames, slot counts, limits, protocol and ABI versions in one plain JS module under public/audio-workers (importable by TS through a typed `.d.ts`) or generate the JS from TS at build. Resolves: the 16_384 and 64/256/128 copies (TS, host JS, worker JS), the version copies, the three dead worker constants, and the substring tests that pin them. Risk: low-medium (values stay the same).
5. **Split AudioEngine along the runtime seams and delete the pass-throughs.** Expose the runtimes (or small facades: `engine.instruments`, `engine.mixer`, `engine.master`, `engine.recording`) and move calibration and transient MIDI mapping into their own modules. Resolves: 42 pass-throughs, the dead engine methods, the engine re-exports, test-only scheduler parameters. Risk: medium (about 100 call sites in src; mechanical).
6. **Dispose helper for Web Audio nodes.** One `safeDisconnect(node, ...targets)` / `disposeNodes` owner replaces the ~36 empty catches and the two edge disconnect copies. Risk: low-medium (assert the exception is the already-disconnected InvalidAccessError instead of swallowing everything).
7. **Move characterization and reference DSP out of the shipped package.** The four `*-characterization.ts` modules, spectral-core, granular-core and `computeCompressorWorkletCurveDb` go to a dev-only package or tools/, together with their tests. Resolves: about 2,200 lines of surplus and the characterization fixtures that must follow every kind. Risk: low (one route and the certification expectations reference them).
8. **Use package imports across the four packages, and drop `export` on 157 own-file-only symbols and the 18 dead ones.** Risk: low.
9. **Split export-mixdown.ts** into route selection, offline instrument renderers, stem planning and the renderer. Resolves the 6-reasons item. Risk: medium (most-changed file; test coverage in export-mixdown.test.ts, 20 tests).
